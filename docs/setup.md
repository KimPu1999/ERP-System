# Setup and verification

## Required tools

- PHP 8.3+, Composer 2+
- Node.js 22+, npm 10+
- Docker Desktop

## Environment

`backend/.env.example` contains local PostgreSQL, Redis, queue, and Sanctum settings. `apps/web/.env.example` contains the browser API URL. Copy them to `.env` files and keep those files untracked.

## Verification commands

```bash
docker compose -f infrastructure/docker-compose.yml up -d postgres redis
cd backend && php artisan migrate && php artisan test
cd ../apps/web && npm run check && npm run lint && npm run test -- --run && npm run build
```

The health endpoint reports application, PostgreSQL, and Redis status. It returns HTTP 200 when all are available and HTTP 503 otherwise.

Tenant data requests must provide `X-Tenant-Id`. The API validates membership before entering tenant context, and clears the PostgreSQL session setting after every request and tenant-aware queued job.

The SPA must first call `GET /sanctum/csrf-cookie`, then use credentialed requests. Authentication uses the Laravel session cookie; no automatic Super Admin login exists. Tenant and platform operations require verified email, and platform access additionally requires the server-side `is_platform_super_admin` flag.

Inventory quantities are changed only by posting validated stock movements. Adjustments, transfers, and stock counts use tenant-scoped idempotency keys and database transactions. Internal barcodes are generated by the API and are distinct from optional GS1 identifiers.

Procurement state changes are recorded in `procurement_document_history`. Goods receipt posting dispatches `GoodsReceiptPosted` as a domain event for a future accounting integration; this phase does not create journal postings.
