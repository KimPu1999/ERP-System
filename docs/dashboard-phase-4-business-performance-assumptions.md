# Dashboard Phase 4 business-performance assumptions

- **Recent transactions:** the endpoint returns only tenant-scoped issued/paid sales invoices, valid credit notes, verified customer payments, approved/posted supplier bills, and posted journal entries. Draft, cancelled, void, rejected, and unverified records are excluded.
- **Date semantics:** invoice, credit-note, supplier-bill, and payment timestamps use the selected company timezone through the shared dashboard analytics context. Journal entries use their posted accounting date.
- **Company and branch scope:** every request requires Sanctum authentication, verified email, active tenant membership, reports.view, and server-side company/branch authorization. Payments are included in a company/branch view only when an allocation links them to an authorized sales invoice. Supplier bills are company/branch-scoped through their purchase order because the current supplier-bill schema has no direct company or branch columns.
- **Transaction detail links:** the current frontend has module-level routes but no verified detail routes for all returned transaction types. The API therefore returns detail_path: null and the UI does not render a misleading detail button. Module-level "View all" navigation uses existing routes.
- **Sales ranking:** posted sales-invoice line revenue is normalized with each invoice exchange rate, valid invoice-level credit notes are allocated proportionally across that invoice's lines because credit notes currently have no product-line table, and received sales returns are deducted using the linked sales-order item price. Sales ranking requires a configured tenant base currency.
- **Volume ranking:** posted invoice quantities less received sales-return quantities are ranked by SKU and unit of measure. Incompatible units are never combined into one total.
- **Currency:** unrelated currencies are not added together. Sales values are reported in the configured base currency; transaction rows retain their recorded currency where available and otherwise expose the base currency fallback or a missing currency state.
- **Boundaries:** both endpoints cap responses at ten records/items and return explicit available, reason, methodology, filters, and pagination metadata.
